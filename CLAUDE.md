# Waterways

Four canvas-animated maps of Florida hydrology (Vite + TypeScript, no framework), plus a Python pipeline that regenerates their data. See README.md for the layout and the data method.

## Commands
- `npm run dev`: dev server on **5180** (preview on 4180), pinned with `strictPort`. Don't move them to 5173/4173; other local projects use those.
- `npm test`: Vitest, which covers unit tests in `src/**` plus data-integrity checks in `tests/data.test.ts`.
- `npm run build`: runs `tsc`, then `vite build`.
- `cd pipeline && uv run waterways <springs|streams|rivers|lakes|aquifer|snapshot|all>` writes to `public/data/`. Tests: `uv run --group dev pytest`.

## Things that aren't obvious from the code
- **Data contracts.** `src/shared/types.ts` defines every file in `public/data/`, and the pipeline writes to match it. If you change a shape, update both sides and `tests/data.test.ts`.
- **Packed coordinates.** Streams and lakes store coords as ints: `(lon + 83) * 1e4`, `(lat - 29.5) * 1e4`. The encoder is `pipeline/.../geo.py:pack`; the decoders are `src/rain/network.ts` and `src/shared/lakes.ts`.
- **Aquifer grids.** Base64 uint8 half-feet, row 0 south. They are gridded with the "two nearest distinct contour levels" method, which reproduces the original chat-built grids to a median of 0.0 ft. FGS contour features are statewide MultiLineStrings; never join their parts (`geo.line_parts`), or phantom lines cross the basin.
- **The rain map's study area is a union of boxes** (`STREAMS_AREAS` in `pipeline/.../config.py`, echoed in `streams.json` `meta.areas`): the basin, the Atlantic corridor to Lake George, the springs belt around them (middle Suwannee, south belt to Crystal River, upper Ocklawaha), up the St. Johns (the middle river and the Wekiva; the upper river; the headwater marshes and the lagoon coast), and the Treasure Coast (the St. Lucie basin and the Loxahatchee). The upper St. Johns boxes step east with the basin's divide to stay out of the Kissimmee basin: NHD routes the Kissimmee and Lake O out the St. Lucie Canal, so a stray creek there would read as Atlantic-bound through Lake O. A new box also widens lakes (`rivers.WATER_AREAS`) and the springs' `onRainMap` flag, and it needs a `VIEWS` entry and a `Zoom to…` option on the rain map. Query sources through `streams.area_query` so overlaps dedupe.
  - Below the study area, ocean main stems run to the sea as `route` segments (now just the St. Johns; the Suwannee's mouth is inside the map). Rain doesn't fall on them, they don't count toward fate shares, and they're exempt from the in-area data test. Each ocean terminal path id (`TERMINAL_GULF`/`TERMINAL_ATLANTIC`) is also its main stem's `levelpathi`, which is how they're fetched. `streams.json` `mouths` lists the segments that end at the sea.
  - The sea is the Census 500k state outlines subtracted from `SEA_CLIP`, plus, in `LAGOON_AREAS`, NHD BayInlet areas (FType 312), since the Census outlines count the Indian River Lagoon as land, and the StreamRiver areas (460) within `coast.TIDAL_DEG` of that water, like the St. Lucie estuary. Only those touching salt water: the St. Johns' own marshes are StreamRiver too. Don't use NHD's SeaOcean polygons for it: they end offshore in watershed-boundary staircases, and some have a handful of vertices. The canvas fills the sea as one shape with no stroke.
- **Springs.** FDEP lists vents separately. Same-base-name vents within 600 m merge, and magnitude uses `MAGNITUDE`/`HIST_MAG` only (`GROUP_MAG` would make every Silver River vent first-magnitude). NHD "artificial paths" are also the centerlines of wide rivers, so only fade the ones inside lakes (`lakes.inLake`).
- **Fates follow NHDPlus routing** (`terminalpa`), not the chat version's hand rules. Rose Creek reaches the Gulf via an NHD underground conduit, so its swallet is listed in `streams.json` `swallets`.
  - Rivers that reach the sea on their own terminal paths (the Withlacoochee, Crystal River, Waccasassa) are sea fates because their last flowline drains into one of NHD's coastline flowlines (FType 566). Those are dropped from the map but kept as `shore` for this test. Don't rely on distance to the Census coast: in marshy bays NHD's shoreline is kilometers inside it. That distance (`coast.COAST_DEG`) is only a fallback for unlinked creeks, and a mapped sink beats it.
  - Water leaving the map takes its terminal path's fate when that path's last flowline (hydroseq == terminalpa) ends on the coast. `coast.PENINSULA_SPINE` decides Gulf vs. Atlantic.
- **NHD sources.** `nhd.query` reads the boxes in `C.BULK_AREAS` from USGS's bulk NHDPlus HR file geodatabases (one per 4-digit HUC, downloaded into `pipeline/cache/nhdplus_hr/` and read with pyogrio) and sends every other box to the map server. The map server times out on big queries, so new boxes go in `BULK_AREAS`. Both are the same release: a comparison of 10,000+ flowlines matched on every id, network link, name, type, length, and vertex, so the older boxes' cached map server responses don't need refetching. Bulk flowlines are only the ones in the flow network (`NHDPlusFlowlineVAA`), as on the map server. A box that straddles two HUCs lists both.
- **Rendering.** `src/shared/streaks.ts` batches particle streaks per style group, one `stroke()` per group. It uses additive glow in dark mode only. Dense rivers saturate to white under additive blending, so they need low alpha. On the rain map, drops also merge (`MERGE_KEEP`) when they enter a bigger stream class. The rain map's creeks are batched too: one `Path2D` per line style, built once in map units and stroked through the camera transform, because the base layer redraws on every pan and zoom frame. A new per-creek style has to become part of the stroke group key.
- **Theme.** Colors are CSS custom properties in `src/shared/tokens.css`. The canvas reads them via `cssVar()` and re-reads them on color-scheme change. Keep them plain hex/rgba; `light-dark()` would break the canvas.
- **The Rainbow River map** (`rainbow.html`, `rainbow.json` from `pipeline/.../rainbow.py`).
  - Its six gauges share `config/gauges.json` and `snapshot.json` with the Santa Fe map; `page` says which map draws each, and the aquifer steps only average the Santa Fe ones (`FLOW_KEYS` vs `RAINBOW_KEYS`).
  - The springshed is SWFWMD's, not traced. Tracing groundwater down the FGS contours fails here: Rainbow isn't a low point in the regional surface (heads keep falling west to the Gulf), so paths slide past it, and the contour interpolation leaves pits that trap them.
  - Keep only geometry from FDEP's BMAP/PFA layers; their records include staff contact details.
  - Below Dunnellon the US 41 gauge sits in Lake Rousseau's backwater and swings with the dam, so the model uses Holder + the Rainbow instead. At Inglis, water splits by the dam and bypass gauges: NHD routes the dam's releases into the barge canal and the river's main stem through the bypass.
  - The map's dark spring/tannin colors fail a line chart's lightness band, so the history chart uses `--chart-spring` / `--chart-tannin` (checked with the dataviz validator).
- **The St. Lucie map** (`st-lucie.html`, `st-lucie.json` from `pipeline/.../stlucie.py`).
  - Only the St. Lucie Canal's two structures are live: S-308 at Port Mayaca and S-80 at the St. Lucie Lock. Both are `signed` in `config/gauges.json`: USGS reports flow back toward the lake as negative, and both `usgs.reading` and `live.parseLatest` keep negatives only for signed gauges (sentinels like -999999 are always dropped). Don't "fix" negative S-308 readings; the canal really runs backward when the lake is low.
  - The model (`src/st-lucie/flow.ts`) splits the canal's runoff at a divide when it runs both ways. Everything else about the canal is derived from those two gauges.
  - The North Fork, C-23, and C-24 are SFWMD structures. DBHYDRO's API needs credentials SFWMD issues, so they aren't animated. Don't commit keys for it.
  - Salinity stations are `config/salinity.json`. Each has a surface and a bottom sensor, and latest-continuous values don't say which is which, so both the pipeline and the page map `time_series_id` to depth through `time-series-metadata` (`sublocation_identifier` "TOP…"/"BOTTOM…"). `snapshot.json` carries them under `ppt`.
  - The Census 500k outlines treat the estuary, the Indian River Lagoon, and Lake Okeechobee as land. The page's sea is the Census sea plus two NHDArea types: StreamRiver (460, the estuary and lower forks) and BayInlet (312, the lagoon, coves, and inlet). NHD has no Estuary waterbodies here.
  - The flow-history chart and the story-page CSS are shared (`src/shared/history.ts`, `src/shared/story.css`) with the Rainbow page. The chart handles negative values. `--chart-lake`/`--chart-estuary` and the map's `--lakewater` passed the dataviz validator against `--tannin`. Green next to brown is the red-green color-blind pair, so re-run it before changing them.
- **The Lake Okeechobee map** (`lake-o.html`, `lake-o.json` from `pipeline/.../lakeo.py`).
  - Its gauges are the `lake-o` entries in `config/gauges.json` plus the St. Lucie map's S-308; the page picks them by key (`LAKEO_KEYS`). All the canal structures are `signed`. Fisheating Creek isn't.
  - NHD routes the Kissimmee across the lake and out the St. Lucie Canal as one level path, and it starts other canals mid-lake, so `lakeo.cut_at_shore` cuts every path at the lake (inflows keep the part above it, outlets the part below). NHD's Miami Canal path starts a few miles south of S-354, so the page runs it up to the gauge.
  - "South" in the history is S-351 (Hillsboro + North New River) plus S-354, summed only in years all three report. S-352 (West Palm Beach Canal) has no USGS record after 2008, and S-65E (the Kissimmee) none after 2004, so both are drawn but not animated.
  - The chart's three colors (`--chart-tannin` west, `--chart-estuary` east, `--chart-spring` south) passed the dataviz validator together, in both modes.
- **The statewide springs map** (`springs.html`) draws `springs.json` (the journal's list) over `statewide.json` from `pipeline/.../statewide.py`. Snorkel spots are hand-curated in `config/snorkel.json`: `springs` flags journal springs by id, and `spots` are the rest, with ids in the springs' `name--county` form that must never equal a spring's (a data test checks), located from OpenStreetMap (keep the `osm` ref and the credit). Coastal lagoons are `statewide.LAGOONS`, NHD features by name from the bulk files; keep river-mouth estuaries like Tampa Bay out. FDEP's first-magnitude count is inflated by vent-level entries such as "Gainer Spring #1a"–"#1i", so the page never states it. Don't "fix" that by widening the vent merge: spring ids are stored in journal visits.
- **Live gauges.** They use `api.waterdata.usgs.gov/ogcapi/v1` (the legacy `waterservices.usgs.gov` is retired in early 2027). That API's default page size is 10, so always pass `limit`.
- **Deploy.** Pages builds via Actions; the six-hourly deploy refreshes `snapshot.json` in the build only, without committing, and pings the journal database so it stays awake.
  - A daily watcher in the private `paperhurts/admin` repo backs this up. It pings the journal too, and emails if this deploy is disabled or the repo goes 50 days without a push (GitHub pauses scheduled workflows in public repos at 60).
  - The watcher reads `url` and `publishableKey` from `config/supabase.json` on main, so keep that file's path and shape stable.
- **Hosting.** The site lives at `waterways.paperhurts.dev`: a Pages custom domain, backed by a CNAME record `waterways` → `paperhurts.github.io` at Namecheap. The Supabase Site URL points at `https://waterways.paperhurts.dev/journal.html`. The `paperhurts-dev` repo topic adds this project to the paperhurts.dev homepage. Log cross-project follow-ups in the private `paperhurts/admin` repo (`C:/dev/admin`).
- **Spring journal.**
  - It runs on Supabase project `pbswebsavanetmieodsf`; the schema is in `supabase/migrations/`. Apply new migrations with the Supabase MCP `apply_migration`, commit the SQL too, and run `get_advisors` afterward.
  - Access is enforced by RLS through `private.is_member()`, which checks the JWT email against `public.members`. The helper deliberately lives outside the API schema.
  - Sign-up is members-only too: the "Before User Created" auth hook (`private.hook_members_only`, enabled in the dashboard) refuses to create accounts, and so to send sign-in emails, for addresses not in `public.members`.
  - Sign-in emails go out through custom SMTP, because the built-in sender only reaches the Supabase team. That's Resend (connected with its Supabase integration), sending as `journal@paperhurts.dev`. Its DKIM, `send`/`rsend` CNAME, and DMARC records are at Namecheap alongside the domain's email forwarding. The templates are in `supabase/templates/`; paste any changes into Authentication > Emails.
  - Spring ids come from `springs.py` (name + county slug) and are stored in visits, so never change the id scheme without migrating `visits.spring_id`.
  - The maps load journal code only when `hasStoredSession()` is true (`src/journal/session.ts`), which keeps supabase-js out of public map bundles.
  - Test UI changes with `journal.html?demo` on the dev server.
  - On the public maps, tapping a journal sighting or a visited spring opens its entries (`journal-overlay.ts`). Popups name people by `display_name` only, never email, and escape all member-entered text. The layer only loads for signed-in members, so to preview a card on the dev server, import the module in the console and call `sightingCard` / `journalCardHtml` with sample data.
  - Wildlife group ids must match the DB check constraint (`tests/journal.test.ts`). Their colors are the dataviz reference categorical palette in fixed slot order, so don't reorder them without re-running its validator.
- **Python.** The pipeline targets Python 3.14 (`pipeline/.python-version`); numpy and shapely ship wheels for it.
- **No PII in the repo.** Keep local paths, usernames, emails, and machine-specific setup out of committed files, including comments and CLAUDE.md. Data files hold only public geographic names from USGS/FDEP/FGS.
